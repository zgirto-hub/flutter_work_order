# Implementation Plan: Link Payment Certificates to Letters (Merged PDF Export)

**Branch**: `029-link-cert-letter` | **Date**: 2026-04-07 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/029-link-cert-letter/spec.md`

## Summary

Enable letter authors to attach existing payment certificates to a Letters v2 letter from the letter form, persist the link via the existing `payment_certificates.letter_id` FK, and produce a single combined PDF on export. Because letter PDFs are generated server-side (reportlab) while payment-certificate PDFs are generated client-side (Flutter `pdf` package via [frontend/lib/services/pdf/payment_certificate_pdf_service.dart](../../frontend/lib/services/pdf/payment_certificate_pdf_service.dart)), the merge is orchestrated by the frontend at export time: the client generates each linked cert PDF locally, POSTs them as multipart to a new backend endpoint which builds the letter PDF and appends each cert PDF with `pypdf`, returning the combined file.

## Technical Context

**Language/Version**: Python 3 (backend), Dart 3.x / Flutter 3.x (frontend)
**Primary Dependencies**: FastAPI, Supabase Python client, reportlab, **pypdf (NEW)** (backend); http, supabase_flutter, Flutter `pdf`, existing `PaymentCertificatePdfService` (frontend)
**Storage**: Supabase (PostgreSQL) — existing `generated_letters`, `payment_certificates` (`letter_id` FK already present; add `letter_link_order int` column for ordering)
**Testing**: Manual quickstart + existing backend smoke tests
**Target Platform**: Flutter Web (PWA) + Linux FastAPI server
**Project Type**: Web application (backend + frontend)
**Performance Goals**: Combined PDF export completes in < 10 s for a letter with up to 3 certificates
**Constraints**: Nginx 50 MB upload cap applies to multipart cert PDFs; single-request export
**Scale/Scope**: 1 form enhancement, 1 new endpoint, 1 migration, ~200 LOC backend + ~300 LOC frontend
