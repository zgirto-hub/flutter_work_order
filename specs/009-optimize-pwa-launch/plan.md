# Implementation Plan: Optimize iPhone PWA Launch Performance

**Branch**: `009-optimize-pwa-launch` | **Date**: 2026-04-03 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/009-optimize-pwa-launch/spec.md`

## Summary

Reduce iPhone PWA cold start from ~30 seconds to under 10 seconds through three independent optimizations: (1) enable Nginx gzip compression to reduce asset transfer by ~75%, (2) implement proper service worker caching for instant repeat launches, and (3) defer non-critical initialization to show UI faster.

## Technical Context

**Language/Version**: Dart 3.x / Flutter 3.x (frontend), Bash (deploy scripts), Nginx (server config)  
**Primary Dependencies**: Flutter Web (canvaskit renderer), OneSignal SDK, Supabase, Nginx  
**Storage**: N/A (no data model changes)  
**Testing**: Manual performance testing on iPhone PWA (4G, 3G throttled)  
**Target Platform**: iOS Safari PWA (primary), Android/desktop (must not regress)  
**Project Type**: Mobile/web PWA  
**Performance Goals**: Cold start < 10s (4G), repeat launch < 5s, splash visible < 3s  
**Constraints**: Fonts must not be modified; canvaskit renderer stays; single Linux server behind Nginx  
**Scale/Scope**: 3 independent optimization stories across server config, service worker, and app init

## Current Bottleneck Analysis

### Download Phase (~15-20s on 4G uncompressed)

| Asset | Uncompressed | Gzipped | Savings |
|-------|-------------|---------|---------|
| main.dart.js | 7.4 MB | 1.7 MB | 77% |
| canvaskit.wasm | 6.9 MB | 2.75 MB | 60% |
| Calibri fonts | 3.2 MB | ~1.5 MB | 53% |
| Other assets | ~1 MB | ~0.5 MB | 50% |
| **Total** | **~18.5 MB** | **~6.5 MB** | **65%** |

### Initialization Phase (~10-15s)

| Step | Blocking? | Estimated Time |
|------|-----------|---------------|
| .env load | Yes | 100-300ms |
| Supabase.initialize() | Yes (network) | 3-10s on cellular |
| OneSignal SDK load | Partially (defer) | 1-2s |
| OneSignal.init() | Yes (inline script) | 500ms-1s |
| Flutter engine bootstrap | Yes | 2-3s |

### Repeat Launch (currently = cold start)

Service worker unregisters itself → no caching → every launch re-downloads everything.
