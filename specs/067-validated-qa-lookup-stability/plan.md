# Implementation Plan: Validated-QA Lookup Stability

**Branch**: `067-validated-qa-lookup-stability` | **Date**: 2026-04-15 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/067-validated-qa-lookup-stability/spec.md`

## Summary

Add a fast-path validated-QA lookup against the raw user question *before* the query rewrite stage runs. On a hit, return the cached Verified Answer immediately and skip the rest of the pipeline. On a miss, fall through to the existing rewrite → existing post-rewrite validated-QA check → HyDE → retrieval → generation flow unchanged. This fixes the observed alternating hit/miss behavior (SC-001) without breaking the context-dependent follow-up case that motivated today's rewrite-first layering.

**Technical approach**: Introduce a single pre-rewrite call to `validated_qa_service.check_validated_match(question, detected_system=detected_system)` inside `manual_rag_service.ask(...)` in [backend/services/manual_rag_service.py](../../backend/services/manual_rag_service.py), returning the same shape the existing direct-match branch already returns. No changes to `validated_qa_service`, the DB schema, embeddings, threshold, or the rewrite stage itself.

## Technical Context

**Language/Version**: Python 3.10 (backend)
**Primary Dependencies**: FastAPI, httpx, Supabase Python client, existing `ollama_embedder` and `validated_qa_service` — **no new dependencies**
**Storage**: Supabase (PostgreSQL) with pgvector — existing `validated_qa` table, existing `search_validated_qa` RPC. **No schema changes, no migration.**
**Testing**: pytest (backend), existing `backend/tests/` harness with `conftest.py`
**Target Platform**: Linux server (Zorin OS) running FastAPI under `document_server.service`
**Project Type**: Web service (backend-only change for this spec; no frontend work)
**Performance Goals**: Cache-hit path ≤ 2 s end-to-end (SC-002). Pre-rewrite lookup adds one vector similarity RPC (~300–800 ms observed in existing path) to the cold path; removes rewrite + HyDE + retrieval + rerank + generation on hits (net 15–25 s saved on hit).
**Constraints**: Must not regress the context-dependent follow-up case (SC-003). Read-path only — FR-007 forbids any writes to `validated_qa`. Must preserve activity-log audit behavior (FR-006).
**Scale/Scope**: Single FastAPI endpoint path (`/manuals/ask`). Estimated code change: ~30 added lines, ~0 deleted, in one file. Two new unit tests.
