# Feature Specification: Cleanup Dead Letters V1 Code

**Feature Branch**: `036-cleanup-dead-letters-v1`  
**Created**: 2026-04-11  
**Status**: Draft  
**Input**: User description: "Clean up dead code from old letters v1 feature (backend/routers/letters.py) and all related frontend service methods, unused dependencies, and router registrations"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Remove Old Letters V1 Backend Code (Priority: P1)

As a developer maintaining the project, I want the old letters v1 backend router and its registration removed entirely, so that no unused endpoints are exposed and the codebase is cleaner.

**Why this priority**: The old v1 backend exposes 5 unused API endpoints that could confuse developers and pose unnecessary attack surface. All functionality has been fully migrated to letters v2.

**Independent Test**: After removal, the application starts without errors. All v2 letter endpoints continue to work. No v1 endpoints respond (should return 404).

**Acceptance Scenarios**:

1. **Given** the backend is running after cleanup, **When** a request is sent to any v1 endpoint (`POST /api/letters/generate`, `GET /api/letters`, `PUT /api/letters/{id}`, `POST /api/letters/{id}/regenerate`, `PATCH /api/payment-certificates/{id}/link-letter`), **Then** the server returns 404
2. **Given** the backend is running after cleanup, **When** a request is sent to any v2 endpoint (`/api/letters-v2/*`), **Then** the endpoint responds correctly as before
3. **Given** the old letters v1 router file has been deleted, **When** the backend starts, **Then** no import errors occur

---

### User Story 2 - Remove Dead V1 Service Methods from Frontend (Priority: P2)

As a developer maintaining the frontend, I want unused v1 service methods removed from the letter service, so that the service file only contains actively used v2 methods.

**Why this priority**: Dead service methods create confusion about which methods are current and add maintenance burden. They reference endpoints that will no longer exist after backend cleanup.

**Independent Test**: After removing dead methods, the Flutter app compiles without errors and all letter v2 features (create, edit, regenerate, export) work correctly.

**Acceptance Scenarios**:

1. **Given** the dead v1 methods (`fetchAll`, `generate`, `regenerate`, `update`, `linkPaymentCertificate`) are removed from the letter service, **When** the frontend is compiled, **Then** compilation succeeds with no errors
2. **Given** the cleanup is complete, **When** a user creates, edits, or regenerates a letter in the app, **Then** all v2 functionality works as before

---

---

### Edge Cases

- What happens if any other module imports from the old v1 letters router? All cross-imports must be verified before deletion.
- What happens if `reportlab` is used by any other backend module (e.g., work order PDF export)? Must verify before removing the dependency.
- Existing database records generated by v1 are unaffected since the `generated_letters` table is shared and v2 reads the same data.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The entire old letters v1 backend router file MUST be deleted
- **FR-002**: The v1 router import and registration MUST be removed from the backend application entry point
- **FR-003**: Dead v1 methods (`fetchAll`, `generate`, `regenerate`, `update`, `linkPaymentCertificate`) MUST be removed from the frontend letter service
- **FR-004**: Backend dependencies (`arabic-reshaper`, `python-bidi`, `reportlab`) MUST NOT be removed — they are also used by `reports.py`
- **FR-006**: All existing v2 letter functionality MUST remain fully operational after cleanup
- **FR-007**: The backend MUST start without import errors after cleanup
- **FR-008**: The frontend MUST compile without errors after cleanup

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Zero dead v1 letter endpoints are accessible after cleanup
- **SC-002**: Zero compilation or import errors in both frontend and backend after cleanup
- **SC-003**: All v2 letter features (create, edit, regenerate, export with attachments, image upload) continue to function identically
- **SC-004**: No shared dependencies are accidentally removed (reportlab, arabic-reshaper, python-bidi remain for reports.py)
- **SC-005**: All dead v1 service methods are removed from the frontend

## Assumptions

- The `generated_letters` database table is shared between v1 and v2 and should NOT be modified
- All frontend screens have already been migrated to use v2 endpoints exclusively
- No external systems or third-party integrations call the v1 endpoints
- Old specification artifacts in the specs directory are documentation and do not need to be deleted as part of this cleanup
- `reportlab`, `arabic-reshaper`, and `python-bidi` are confirmed used by `reports.py` and MUST NOT be removed
